# 研发路线

## 已建立的基础

独立规则库、搜索接口、评估器生命周期、两种原生入口、网页/桌面、
共享契约、训练数据闭环和跨语言测试。正式训练框架已接通数据分片、
WDL/policy 网络、混合监督、单设备训练、断点恢复和量化导出/整数参考。
网页已接通 WASM 引擎、同机人人/人机/机机对弈及暂停、单步、取消竞态保护。
当前骨架的用途是让后续迭代有统一入口和回归依据。

## 下一阶段：搜索基线

先补强战术正确性与固定局面集，再加入置换表、PVS、历史启发和更好的着法排序。
增加时间管理测试和固定开局集，记录搜索节点、耗时、候选着覆盖与对战结果。
VCF/VCT 与选择性剪枝必须包含漏防/漏杀回归用例。

## NNUE

正式架构见 [NNUE 正式架构](nnue-design.md)，已实现部分见 [训练框架](../training/README.md)。
小型 MLP 入口已替换为 `line11-dual-v1`。同一份网络可选择 CPU、Intel XPU 或 NVIDIA CUDA；
本机 CPU/XPU 已执行检查，CUDA 待在对应硬件验证。当前执行器为单进程，DDP 尚未实现。

真实 Rapfi NNUE 教师的自对弈采集、binpack 转换、规则核验和数据清单已经接通，
详见 [教师工具](../tools/README.md)。同一网络可直接蒸馏这些真实评分与最佳着法。

C++/WASM 模型加载、双头增量推理、跨语言精确一致性、完整对局与静态网站发布已接通。
下一步扩大数据与训练预算，补齐固定条件下的棋力对战与模型晋级，并优化 SIMD 吞吐。

少量样本用于验证正式实现，不开发随后丢弃的小网络或数据格式。
网络宽度和数据量通过配置调整；全量推理长期保留为增量更新的校验依据。

保留手工评估器作为对照。通过显式模型格式拒绝不兼容权重，
不把训练框架或模型下载逻辑放进比赛程序。

## 规则与比赛

根据优先参赛分组推进规则。Renju 的禁手判断需要完整规则测试；
Caro、Swap2 也应独立验收，不能只增加一个枚举值。
然后使用官方裁判软件验证重启、开局导入、时间、内存、协议和干净 Windows 发布包。

当前不宣称具备参赛棋力，也不把脚手架测试等同于官方验收。

## 网站产品化

保持本地 MatchController、统一 Engine 接口及独立 HTTP SDK 的边界，逐步加入
棋谱导入、复盘/分析模式、搜索进度订阅、浏览器缓存和棋局恢复。
需要联机对局时由服务器裁定共享棋局与身份，客户端 WASM 可继续负责 AI/分析；
同时推进持久化、访问控制与容量策略。
